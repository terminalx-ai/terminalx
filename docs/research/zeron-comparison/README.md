# Zeron and TerminalX: fresh-install comparison

**Test date:** 26 October 2026, Asia/Dubai (recording began 25 October UTC).

**Zeron:** v0.2.125, commit `255c540d651910ccab451b77ec59c05ba4266d41`.

**TerminalX:** 0.2.19, source commit `e86b2de2db8968739d75e85ae0e859b38e95a862`.

This is a product and usability investigation, not a performance benchmark or a security audit. The deliverables are a feature comparison, an evidence ledger, a narrated video, and an actionable improvement backlog. No application behavior was changed.

**Start here:** [Watch the narrated comparison](video/comparison.mp4) · [Read the 14 prioritized improvements](improvements.md) · [Video transcript and chapters](video/README.md) · [Validation results](validation.md).

**Status: local comparison complete.** Both fresh installations were exercised in separate Lume VMs. Authenticated inference, production installation/update, cloud/sync and voice remain outside the executed scope; their presence is distinguished from a runtime pass.

## Scope and reproducibility

Each application was installed in its own clone of the same Lume macOS base: macOS 26.5.2 (25F84), four virtual CPUs, 8 GiB RAM, a 150 GiB virtual disk and a configured 1440 × 900 display. The pre-existing `terminalx-ui-pilot` VM was left alone. See [environment.json](environment.json) for artifact hashes and VM names.

Zeron used its published Apple Silicon application archive. TerminalX used the repository's Dev variant, built from the exact commit above with `pnpm tauri build --debug --bundles app`. The build used the existing Dev identity, development helper/launcher/runtime hooks, and disabled updater artifact generation. This is a fresh installation of current project code, **not a test of the signed production installer, production account endpoints, or updater**. Debug-versus-release timings and memory figures would not be comparable, so none are ranked here.

No provider credentials, personal projects, host app profiles, or existing conversations were copied into either VM. Zeron installed Codex 0.164.0 through its onboarding UI. TerminalX received the same standalone Codex 0.164.0 binaries, with no credentials or configuration copied. Both runs selected GPT-6.1 Sol / High and sent `read readme.md`. The fixture repository contains only a README and a JavaScript task list. A later README addition was made by the test operator: through the setup shell for Zeron and through TerminalX’s editor for TerminalX. Neither was an agent-generated change.

The first Zeron pass used `terminalx computer` against Lume’s viewer. After the user requested background VM testing with trycua, TerminalX was controlled directly through the guest’s Cua Spacesd 0.7.0 service. Host desktop focus and keyboard input were not used during this continuation. Lume SSH and Cua’s guest process/file APIs handled installation and verification. The guest service’s existing Accessibility and Screen Recording grants were used; no host permission repair was needed. [Cua’s architecture](https://github.com/trycua/cua/blob/main/libs/cua-spacesd/README.md) documents this guest service.

The configured VM display was 1440 × 900, but the TerminalX continuation reported an actual 1024 × 768 guest desktop, with a 1024 × 675 app window (680 high after reopening). Viewer resizing affects screenshots. This is not an equal-viewport visual-density score. The video uses genuine VM footage and screenshots, editorial captions and local synthetic narration; it does not imply a successful authenticated coding run.

## What was exercised

Zeron: onboarding, inline Codex installation, local project selection, model/effort/checkout controls, worktree creation, signed-out failure, terminal `pwd`, Markdown preview, working-tree diff, browser navigation, settings and light/dark appearance.

TerminalX: fresh start screen, external install handoff, agent re-check, local project picker, model/effort/permission/worktree controls, signed-out launch recovery, same-process agent terminal, a separate shell, Markdown preview, editor/save, diff scopes, Git history, browser navigation, settings, dark mode, command-palette file search, Needs you dashboard, desktop-process restart and stopping the agent. [Runtime evidence](evidence.md) records exact outcomes and limits.

Neither app completed the coding prompt: Codex was intentionally signed out. Zeron surfaced an authentication error. TerminalX created the worktree, initially showed Working, then reported unconfirmed prompt delivery; its terminal exposed Codex’s sign-in flow. This difference supports a specific readiness/recovery recommendation.

## Main finding

Zeron makes the journey from an empty Mac to a configured workspace unusually explicit: appearance, optional sync, an agent installer, then a project. The composer keeps project, device, model, effort, branch and checkout choice close to the prompt. Its adjacent terminal, file, diff and browser surfaces support a focused workspace.

TerminalX already has many of those capabilities. Its distinctive strengths are the real agent CLI behind both chat and terminal, a cross-project attention dashboard, GitHub/Linear issue entry points, independent review pipelines, configurable permission modes, and a supported automation CLI. The strongest near-term opportunities are **agent readiness and onboarding, authentication-aware recovery, and restoring workspace context after a desktop restart**. A fresh TerminalX composer initially selected missing Claude Code even though Codex was installed. Its agent and local runtime survived desktop-process termination, but the browser tab was absent after reopening. Adding a theme, shortcut editor, command palette, browser or diff viewer as if absent would misdiagnose the gap.

## Recommended implementation order

See [improvements.md](improvements.md) for acceptance criteria, evidence and effort. Start with agent setup/readiness and authentication-aware recovery. Next, improve launch hierarchy, workspace restoration and tool discovery. Validate the current-plan tray and screen-context draft with authenticated users. Provider expansion and theme imports follow product validation, not checklist parity.

## Validation and limits

- `pnpm install --frozen-lockfile` completed without lockfile changes.
- `pnpm check` passed: TypeScript plus 289 test files / 3,387 tests.
- The frontend and native Dev application build completed successfully.
- Successful agent inference, paid cloud creation, sync, GitHub/Linear writes, voice recording, Appshots capture, normal-Quit semantics and update installation were not tested.
- Baseline and artifact checks are in [validation.md](validation.md). Both comparison VMs are retained and stopped; unrelated VMs were not changed.
- Zeron's older `docs/PARITY.md` contains historical statements contradicted by the installed release, including an always-dark UI description. Current code and observed behavior take precedence over that checklist.
- VM viewer input/geometry issues are capture-environment limitations, not automatically defects in either app. No frame-rate, CPU, memory, battery, accessibility-compliance or time-to-productivity ranking is supported by this run.
