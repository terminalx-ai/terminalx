# Two-account desktop harness foundation (PRO-249)

Phase 2 wave 1 provides scenario contracts, isolated environment helpers, immutable
artifacts and lifecycle failure tests. **Actual server/native scenario coverage is
pending for every scenario. This checkpoint cannot certify E2E or return a passing
real-run result.** It starts no server, Docker provider, desktop, VM or remote job.

Run from the terminalx repository root (no package.json changes required):

```sh
node --test scripts/team-e2e/*.test.mjs
node scripts/team-e2e/run.mjs --preflight --artifacts /tmp/team-e2e-artifacts
```

The second command exits 2, writes a run-owned `team-<UUID>/result.json`, and names
actionable prerequisites. Omitting `--preflight` still exits 2 and explains the
missing execution driver. Exit 1 denotes failure; exit 0 is reserved for future
verified execution and is unreachable in this checkpoint. No fixture observations
are generated by the runner. Contract test fixtures are assertion tests only.

An optional `--config /absolute/local-config.json` can document intended setup:

```json
{
  "apiOrigin": "http://127.0.0.1:42220",
  "serverCheckout": "/absolute/local/server-checkout",
  "machineA": "host-mac",
  "machineB": "second-mac",
  "debugBuilds": true
}
```

Configuration is declarative, unverified input. It cannot enable launches, supply
observations, remove the integration blockers or certify execution. Only explicit
HTTP loopback origins are accepted as local prerequisites; no URL is contacted.
Never supply real tokens or production endpoints. Invalid/missing config files or
unknown CLI arguments exit 1 before allocating an artifact run.

## Integration prerequisites and ownership

The server owner must provide and review a disposable local Docker fixture with
two disposable identities, one organization, an invite addressed to B (initially
not a member), local auth/PKCE, run-scoped resources, readiness manifest and bounded
cleanup. `server:apps/api/scripts/cloudLocalE2e/run.ts` is a known integration
point, not an implementation verified by this work. No paired server changes or
server lifecycle execution are included here. Fixture readiness must eventually
be verified from the running server rather than trusted config booleans.

The native owner must provide two actual macOS product runtimes: host Mac A and a
second Mac or supported macOS VM B. A Linux local VM, browser profiles and two host
windows do not establish two-machine coverage. Record exact desktop/server heads,
run-local machine identifiers, binary hashes, PIDs and account/org/workspace/tab
identities. Arrange reviewed loopback forwarding for B; remote provider origins
must never be substituted for the local fixture.

Both debug apps need separate `TERMINALX_HOME` directories and
`RACCOON_DEV_KEYCHAIN_SERVICE=dev.terminalx.<runId>.<A|B>`, with
`TERMINALX_DEV_API_BASE_URL` pointing at the local fixture. `native.mjs` builds a
restricted environment, dropping inherited coordinator/provider credentials; it
does not launch or sign in. Its snapshot/click helper consumes fresh native state
and invalidates it on refresh failure or after a click. It is not a recorder or a
complete scenario driver. Native accessibility availability remains unverified.
Respect typed refusals and person-only controls; an action acknowledgment is not
an observation. Remote transport, startup, sign-in, navigation and cleanup remain
owner integration decisions.

`scripts/webkit/cloud-session.mjs` uses runtime stubs through the WebKit harness.
It is useful layout evidence, but cannot establish native authentication,
server-side permission enforcement, notifications or two-account E2E coverage.
The capability inventory is a pending integration checklist, not a claim about
which SaaS features have landed. SaaS, design/UI bindings and native certification
remain outside this foundation and require their owners' review.

## Scenario contracts

Every row requires an independent baseline and controlled real break, screenshots
and observation logs bound to the run, plus restored faults and owned cleanup.
Retries preserve earlier failures. Unknown scenarios, skipped phases, wrong
identity, unrelated break failures and cleanup failures cannot turn green.

| Scenario | Required observations | Proposed controlled break |
| --- | --- | --- |
| Invite accept | B absent, invite pending; B becomes member in the same org; invite consumed; A remains owner | Suppress accept |
| Share | B denied before grant; viewer sees the run nonce; no approval right | Suppress grant |
| Viewer read-only | Send, terminal and approval denied; disabled composer; no queued command or transcript mutation | Review isolated denied-probe response fault; never relax authoritative permissions |
| Presence appear | A absent then visible to B with matching identity and tab | Keep A disconnected |
| Presence clear | A disappears while B stays connected | Keep A attached |
| Follow | B tracks A to another tab; unfollow stops subsequent tracking | Suppress follow |
| Mention + notification | Exactly one event to B with actor, nonce, workspace and destination; no duplicate after reconnect | Suppress mention |
| Reassign | Assignee changes A to B on both surfaces; viewer rights unchanged | Suppress reassign |
| Nudge | Exactly one person notification to B with correct destination; reconnect deduplicates | Suppress nudge |
| Unread sync | B's markers converge across two B surfaces; monotonic updates; A unaffected | Suppress B read update |
| Unshare | Existing and subsequent access revoked; content cleared; A retains access | Suppress revoke |

`corruptObservation` deliberately mutates unit fixtures to check assertion
sensitivity. It is never a real feature break or certification evidence. Proposed
break mechanisms still need implementation/review and product-design agreement.
Person follow, mention, nudge and reassignment must use actual product contracts;
agent transcript following, file mentions, runtime nudges and driver leases are
not substitutes. Unread sync compares the same reader across two surfaces.

## Artifacts and lifecycle

Run directories use a random owner ID and private permissions. JSON writes are
exclusive and redact credential keys, bearer strings and callback query secrets.
Screenshots/logs require containment, nonempty bounded files and matching SHA-256;
screenshots require a PNG signature. Review captures for personal/secret content
before any future sharing: JSON redaction cannot sanitize screenshot pixels or
arbitrary raw logs. No actual native screenshots/logs exist in preflight runs.

Retention keeps at most 30 finished owned runs for 14 days; it leaves unfinished,
unrelated and symlinked entries untouched. Only direct children created by the
process helper receive timeout/output-limit termination. It never searches for
host PIDs or prunes Docker resources. Fixture/remote cleanup is still pending.

`evaluateRun` separates pure `assertionStatus` from the overall incomplete result.
`finalizeRun` checks owned evidence files and matching caller-supplied capture
provenance, but cannot prove execution without a native recorder. Even fully
consistent supplied data remains uncertified and exits nonzero.

## Nightly and remaining acceptance criteria

`.github/workflows/team-e2e-nightly.yml` is opt-in via
`TEAM_E2E_ARTIFACTS_ENABLED=true`, main-only, on a dedicated self-hosted macOS runner
and protected environment. It only collects prerequisite artifacts and uploads
them for 14 days; expected exit 2 remains non-green. It posts no job summary,
message or certification. No workflow was activated or run as part of this work.

All ticket acceptance criteria remain pending for the integration phase:

- One command launches both accounts and executes all scenarios: requires reviewed
  local server lifecycle, second Mac, native bindings and remote cleanup.
- Every broken feature fails in a real deliberate-break run: contracts are tested,
  but every real baseline and break still needs recorded native/server evidence.
- Nightly posts its results: deliberately deferred; this phase permits artifact
  collection only. Activation and publishing need a later owner decision.

No production endpoints, billed compute, SaaS edits or result publication are
needed for the foundation checks. This work selectively reuses contracts/helpers
from stale `origin/raccoon/pro-249-two-account-e2e`; its server, landed-feature and
host recovery claims are not treated as current evidence.
