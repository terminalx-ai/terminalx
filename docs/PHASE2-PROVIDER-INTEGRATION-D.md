## Additive shared lifecycle (session-private)

The concrete source signatures are in `session_provider_authority.rs`:

- `OperationContext::reserve_stream() -> Result<StreamReservation>` changes
  Pending to DispatchStarted exactly once. The reservation is noncloneable and
  carries no locks/guards. A clone cannot reserve a second frame/exchange.
- `StreamReservation::try_chunk(live, exact_correlation, witness,
  admit_original_sender, one_syscall) -> Result<(Attempt,
  Option<io::Result<usize>>)>` admits the SAME operation before one synchronous
  nonblocking syscall. Applied plus Some means exactly one invocation, including
  WouldBlock/Interrupted. Deferred/Withdrawn means zero invocations. WouldBlock,
  partial progress and contention leave DispatchStarted without consuming a
  callback or deriving another context. The actual syscall byte count is kept.
- `finish(StreamOutcome::{Refused, Unknown, Response, Complete}) -> bool` is
  once-only. Zero-byte refusal withdraws; uncertain/partial errors are terminal
  UnknownOutcome. Response permits one callback only after a full newline or
  complete HTTP exchange; Complete is terminal delivery for no-response work.
  Reservation drop retires an unfinished attempt; it never resets/replays it.
- `try_confirm(live, witness)` admits an exact known no-wire setting without a
  fabricated syscall, and completes only that reserved Configure operation.
- `OperationContext::stream_current(live)` is a cancellation/parent/association
  poll ONLY, never physical authority. `ProviderBinding::current` remains owner
  private. `bind_queued` is limited to original undispatched queue items;
  `seal_origin` prevents deriving a second prompt after the handoff.

The actual ACP owner calls B's `write_carried_frame` outside admission/runtime.
That writer serializes the whole newline frame on its captured child. Each
at-most-4096-byte syscall reacquires original policy, session admission,
independent privacy/share/mobile/owner attachment, then runtime, then checks
original action/member/source/revision/runtime generation/process epoch/direct
attachment, exact native child Arc/epoch/incarnation and exact adapter request.
Settings/native request and approval attempt gates are checked on every chunk.
No policy/session/runtime/share/mobile/attachment guard survives a chunk return,
frame wait or capacity sleep. Session Hold fences are checked without waiting
under policy. Admission contention retries the same original reservation.

Privacy cleanup tickets are independent counted in-flight I/O leases, not held
policy/sender mutexes. Every original privacy ticket is retained independently,
including mobile/share tickets, and per-syscall admission rechecks them. The
cleanup count is released only after partial-pipe closure/retirement, preserving
privacy acknowledgement ordering. It does not authorize any later syscall.

Only the final full-newline syscall transitions to AwaitingCallback (or terminal
Complete), calls adapter `delivered(id)`, and publishes PromptWrite.started and
ModelRequestStarted once under original admission. A delivered approval consumes
only `answer_current`'s exact attempt, and its card/observer settle on delivery.
On error B closes only its captured partial pipe. D retires only that captured
association if still current, never a replacement. Independent queued successors
remain attributed to their own sender. Old callbacks cannot write a new pipe.

## Preacceptance ACP delivered-result correction (source only)

The carried ACP writer formerly classified a successfully delivered selection by
searching its serialized response for `deny`, `reject` or `cancelled`. Provider
option IDs are opaque. This could mislabel a delivered deny as Allowed, or an
approval as Denied, without changing the provider-selected wire option.

The adapter now retains each request's authoritative option-kind mapping, and
binds the semantic boolean to the exact original answer attempt. Known
`allow_once` / `allow_always` choices allow; `reject_once` / `reject_always` deny.
Missing, unknown or duplicate provider-selected metadata refuses before
producing a response frame. Native `raccoon:cancel` always means the existing
cancelled denial for a pending ask, including when a reject option already
exists; it can never select a provider grant using that reserved ID. The owner publishes a decision only after that exact answer
attempt is delivered: `None` means no current delivery, `Some(false)` means a
delivered denial, and `Some(true)` means a delivered approval. The legacy ACP
owner path uses the same metadata; neither path examines opaque ID substrings.

Five new regressions are authored and **UNRUN**: three `acp_permission_choice_`
adapter tests, plus two `provider_integration_d_approval_` actual-writer tests.
They cover misleading IDs (deny containing allow; approval with no allow or
containing reject/deny), exact unchanged wire selection, native cancellation,
unknown/missing/duplicate mappings, no emitted decision/no frame on refusal,
and actual delivered Allowed/Denied events. The existing original-attempt
replacement test now distinguishes delivered denial from no delivery.
