# Runtime Environment info (PRO-203)

The cloud workspace header offers **Environment info** only when the signed-in account's organization has `cloud.environment-info.v1=true`. Missing/off means no surface and no request. Its Radix popover uses the existing Button, colors, focus handling, Escape and close behavior. Opening it reads that workspace's already-connected runtime; it never wakes a stopped machine.

`environment/1` adds `environment.report` and `environment.cancel` to the existing workspace RPC capability negotiation. Both accept exactly one UUID `requestId`, no command, path, environment variable or tool name. Existing E2EE attachment, workspace authorization and participant membership checks still apply. Cancellation is scoped to the attachment ID; the probe also watches disconnection and authorization loss. There is one active report per runtime process. No report goes through telemetry, the server, local persistent storage or another account.

The runtime probes only Node.js, npm, pnpm, Python 3, git, gh, jq, ripgrep, git-lfs, tmux and vim. Executable candidates are fixed system/curated paths, never a client-supplied PATH. Each process gets a cleared environment, a fixed PATH, `/nonexistent` HOME, `/` cwd, no stdin, discarded stderr, a 4096-byte stdout limit and two-second deadline. Only a short numeric version (plus tmux's letter suffix) leaves the runtime, with a fixed tool/status ID. Errors never include raw output, file paths, environment values or credentials. Process groups are killed on timeout/cancellation, including wrappers' descendants. Probe invocation must integrate the actual landed PRO-244 process/privacy admission contract before release.

The response is `{version: 1, observedAt: <runtime milliseconds>, tools: [...]}`. Every allowlisted tool has `installed` with `version`, or `missing`, `error` or `timeout`. The client requires exactly those 11 IDs, validates versions, and drops additional fields. The image manifest is build provenance, never installed truth. The popover shows loading, error, unsupported runtime, missing tool, disconnected and stale-report states. It marks old/failed-refresh reports stale, offers Refresh while supported, cancels on close/account/workspace/runtime changes, and removes its local state when the account or rollout context changes.

PRO-252 has reserved the flag disabled at 0%; its actual landed registry/migration and server/native RPC kill-switch contract are integration prerequisites. Do not seed or enable a production flag from this change. PRO-191 offering setup, PRO-215 SSH prerequisites and PRO-244 privacy admission remain owned by their existing authors; consume their landed interfaces and revalidate the final heads instead of copying unmerged source. No image metadata migration is introduced.

Focused DTO/UI and provider tests exercise validation and fallback boundaries. Rust tests additionally cover fixed parameters, sanitized output, cleared process environment, limits and attachment-scoped cancellation. Native process tests, normal hooks/full checks, accessible UI interaction, real account/workspace/runtime transport, Docker image builds and real provider boot timing are separate acceptance gates. A source-only review is not committed-head approval or a release. The coordinator holds desktop publication until the paired server passes normal review/checks/CI/security/native gates, merges through TerminalX, and the existing production poller reaches the exact deployed SHA with healthy status.
