# Session rendering after lock and sleep (issue #324)

## Changes and boundaries

Returning through visibility, focus or pageshow, or detecting a delayed webview
heartbeat, refits the visible terminal and replaces its GPU surface. None of
these signals is classified as proof of sleep or a process exit. The existing
xterm and PTY attachment stay alive, preserving normal/alternate buffers and
input. `Redraw terminal` repeats this recovery without writing to the PTY.

Local chat rereads mounted, previously loaded conversation logs and merges by
event identity. Local status is refreshed from the backend, with concurrent
status updates taking priority. Failed reads preserve the last known state and
are retried on the next resume. These reads do not resend prompts or replace
the composer. Cloud transport recovery remains owned by the cloud client.

Hidden local terminal feeds acknowledge parsing, not receipt, avoiding an
explicit bypass of flow control during timer throttling. This is not a hard
queue bound: the backend's existing two-second unresponsive-view escape hatch
still allows the process to run when the webview stops responding altogether.
The screenshots do not establish a single root cause; native validation is
required, especially for sustained output while the webview is suspended.

The existing watcher reports silence as an unknown outcome/needs-attention,
never as a confirmed process exit. Recovery does not clear such a warning
without backend evidence or restart work to try to resolve it.

## Synthetic manual validation

Run in a development build with a disposable folder project and synthetic
conversation only. Do not collect real prompts, paths, session identifiers,
command arguments or account diagnostics in public attachments.

1. Create an agent session containing only a request to print a numbered
   synthetic sequence and then wait. Open a second synthetic session for
   navigation checks. Keep an unsent `synthetic pending draft` in chat.
2. In a peer shell terminal run this bounded synthetic stream:

   ```sh
   python3 -u -c 'import time; [(print("synthetic line %06d" % i), time.sleep(1)) for i in range(7200)]'
   ```

   Record the most recent line number. Scroll upward so viewport preservation
   can be checked. Separately repeat with a synthetic full-screen/alternate
   screen program and with terminal view hidden under chat.
3. **Lock only:** prevent automatic system sleep using the OS settings, lock
   the screen for at least 30 minutes, then unlock. Record duration and verify
   from OS sleep history that this was actually a lock-only run.
4. **Sleep separately:** restore the usual sleep settings, explicitly sleep
   the machine for at least 30 minutes, then wake it. Record sleep duration.
   Do not label a lock-only run as sleep/wake or vice versa.
5. For each run, verify readable terminal content, scrollback, cursor and
   alternate screen; switch terminal/chat repeatedly; scroll chat, edit its
   unsent draft and navigate to the second session and back. Confirm the draft
   and conversation survive and no prompt or command was resubmitted.
6. Repeat with a quiet active agent, a naturally completed agent, and an
   existing needs-attention timeout. Confirm status follows backend facts;
   a timeout means unknown outcome, not exited. Watch new synthetic output
   clear a watcher-generated stall only when the backend confirms progress.
7. Click `Redraw terminal` and verify the same buffer and process remain.
   Where WebGL is unavailable, repeat to verify readable DOM fallback.
8. Repeat with high-volume but synthetic output to look for UI stalls or
   missing numbered lines after the backend's unresponsive-view timeout.
   Record only counts, timing, renderer type and pass/fail, without raw logs.

## Validation record

Automated regression coverage includes coalesced visibility/focus events,
a suspended heartbeat without visibility changes, cleanup on unmount,
renderer replacement/fallback, real xterm buffer preservation, no terminal
input generated by recovery, parsed-byte acknowledgements, concurrent chat
history merging and failed-read retry.

Native long-lock and sleep/wake runs have **not been performed** as part of
this change. Use the procedure above on each supported OS before declaring
those acceptance criteria verified; simulated lifecycle events cannot prove
native GPU or OS behavior.
