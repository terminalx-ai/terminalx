## Actual owner behavior

- Admitted prompt/queue/settings/approval/control ingress routes carried native
  actions to session-owned workers. A NativeHttp is built from the actual
  ProviderAction, retaining its original opaque OperationContext. No callback
  TLS capture, Permit remint, serialized authority or Drive-to-Approve/Configure
  upgrade. Per-item Local/remote/missing-origin queue requirements stay intact.
- Each HTTP operation records exact native binding/incarnation/child epoch,
  engine generation, action tag, operation correlation and original sequence.
  Approval also records the provider request, separate answer attempt, and ask
  incarnation. Repeated same-ID provider asks retire old answer attempts. Old
  callbacks cannot settle a replacement with the same provider session ID/tag.
- Reserve ONCE, reuse the SAME nonclone D StreamReservation at each C FinalWrite.
  Every hook re-enters policy -> session -> independent privacy/mobile/local
  share/owner attachment -> runtime, then checks original action/source/revision/
  runtime epoch/generation/peer and current plus pending TabWitness immediately
  around ONE nonblocking syscall. Deferred calls no syscall. No guards escape
  into connection, capacity, read, callback retry or test-barrier waits.
- C's supplied-hook lifecycle leaves finalization to the owner. Exact returned
  Refused/Unknown/Response maps once to D finish BEFORE callback handling.
  Refused is known zero-byte withdrawal, Unknown is consumed without replay or
  fallback, Response becomes AwaitingCallback. D Drop handles unwind.
- ONE whole-response callback batch validates original sender and exact request
  before touching the pure engine. Opening stash -> prompt, or known failed
  session_get -> session_new, derives original children inside that callback
  before Delivered. Children are scheduled only after callback guards release.
  Unknown never produces a synthetic status=0 callback or session fallback.
  Duplicates are inert; Deferred retains the exact actual reply and context.
- Opening cancellation discards the exact stash and retires old generation.
  Independently queued local successors keep their own authority and can run
  despite retirement/revocation of the original remote opening. An uncertain
  HTTP operation is never replayed as that successor.
- OpenCode has no model/mode RPC. Its real next-prompt snapshot mutation uses
  independent original Configure, exact native settings ID and no-wire D
  confirmation. Existing shared settings settlement handles model and mode
  separately; an old equal-value intent cannot settle the replacement. Opening
  defaults retain separate Local Configure contexts. Prompt preparation retains
  original Drive while waiting outside guards for exact pending Configure
  confirmation, then re-admits that original sender before building the body.
- Approval settlement requires the exact still-current answer attempt and a
  known successful HTTP response. A new deny never inherits an old Allow or
  prompt Drive. Card/observer delivery follows the admitted batch.
- The D production SSE pump retains exact child/binding/incarnation fences.
  Its atomic runtime-held decode/emit now calls the shared owner event entry.
  Output does not require the old prompt's Drive, so a later local turn remains
  visible after remote revocation. Carried stdout/SSE cannot inject synthetic
  HTTP callbacks; physical output-derived actions lacking an exact parent are
  refused. Read-only SSE settings cannot value-ACK pending native requests.

## D no-wire failure diagnosis and correction (source only)

Root supplied failed isolated D evidence locating the final repeated-plan
sidecar barrier; this is NOT a passed D check. The fixture provider returned `{}`
for session/set_mode, while actual frozen B updates current_mode ONLY from an
ACK's modeId. The repeated request therefore generated a second physical RPC,
not the claimed known no-wire action, and its reply was not consumed by that
assertion. E makes the Python fixture echo params.modeId (as B's real fixture
already does). Root's same-context bounded Deferred helper and exact sidecar
assertion are retained. An additional request-count assertion proves that the
known no-wire repeat enqueues no further mode RPC. No production gate was
loosened, no timeout raised, and no value-only model/mode ACK was introduced.
The correction remains UNRUN; no assertion outcome is claimed.
